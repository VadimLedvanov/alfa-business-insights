# Тестовые события для генерации инсайтов

Синтетический каталог из 20 событий под CSV кейса (`backend/core/src/main/resources/data/csv`)
и материалы ЦМИ Альфа-Банка из приложения 2 кейса. Условный 2026 год: ключевая ставка 14,0%
сохранена 11.09.2026. Цифры выдуманы и нужны только для проверки сервиса.

| Файл | Что это |
| --- | --- |
| `events.json` | События в формате `POST /api/events` (`event`) плюс ожидания: фактор влияния, материал банка, селектор целевых компаний, ожидаемые и контрольные компании, тезисы хорошего инсайта |
| `find_targets.py` | Применяет селекторы к полному CSV и платёжному графу; падает, если ожидания расходятся с данными; пишет `targets.md` |
| `targets.md` | Сгенерированный список целевых компаний по каждому событию с их признаками |

## Проверка каталога

```bash
python3 -I tests/events/find_targets.py
```

## Загрузка событий на стенд

События создаёт только `SYSTEM_ADMIN` (пользователь `sysadmin` из тестового realm Keycloak).
Пример для одного события после получения JWT:

```bash
jq -c '.events[0].event' tests/events/events.json | curl -s -X POST http://localhost/api/events \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d @-
```

Инсайт по паре «компания — событие»: `POST /api/companies/{companyId}/events/{eventId}/insight`.
Компании берутся из `expected.companies` и `expected.not_affected` конкретного события.

## Как читать ожидания

- `selector` — формальное правило «кого событие касается» по признакам CSV; второй порядок
  задаётся через топ-5 контрагентов (`counterparty_okved_prefix`) и группу (`group_*`), как в
  `CompanyContext`.
- `expected.companies` — компании, на которых проверяется содержательный инсайт; `not_affected` —
  контроль, для которого событие не должно попасть в топ.
- `expected.features_used` — имена полей `CompanyProfile`/`CompanyContext`, которые должны
  появиться в `features_used` ответа.
- E17–E20 — негативные и защитные сценарии: шум, противоречивые данные, инъекция инструкций,
  событие без извлечённого текста.
